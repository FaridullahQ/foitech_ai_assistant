How it works

From question to answer in three steps

The AI never touches your database. It only writes a small JSON plan, and Odoo checks and runs that plan.

You ask

Type a question in the chat. Any language your chosen AI model understands will work.

Odoo runs a safe query

The plan is limited to search_count, search_read and read_group, executed as you, so access rights and record rules apply.

You get the answer

A clear reply with lists or tables, an optional chart, and a CSV download.

Setup guides

Get running in minutes

Follow the installation guide first, then configure one provider. You can add the others later.

1  Installation All setups
  1. Copy the odoo_ai_assistant folder into your Odoo addons path, or install it from the Odoo Apps store.
  2. Make sure the Python requests library is installed (it is included with most Odoo installs): 
    pip install requests
  3. Restart Odoo, then go to Apps → Update Apps List, search for AI Assistant for Odoo and click Install.
  4. Open Settings and scroll to AI Assistant Settings. Choose a provider and fill in its fields (see the guides below), then click Save.
  5. Click the round button in the bottom-right corner and ask your first question.
Upgrading? Run odoo-bin -u odoo_ai_assistant -d YOUR_DB and hard-refresh the browser (Ctrl+F5) so the new interface files load.
2  Run a local open-source model with Ollama Private

Run the AI on your own computer or server. Nothing is sent to the internet.

  1. Install Ollama from ollama.com/download (Windows, macOS or Linux). On Linux: 
    curl -fsSL https://ollama.com/install.sh | sh
  2. Download a model. Open a terminal and run, for example: 
    ollama pull qwen2.5:14b
    Rough memory needs (4-bit models, check the model page for exact figures): 7–8B models need about 6 GB of GPU or RAM, 14B about 10–12 GB, 30B-class about 20 GB or more. Models of 14B and above give much more reliable answers than small ones.
  3. Check it works. List your models and test the server: 
    ollama list
curl http://localhost:11434/api/tags
    On Windows PowerShell use curl.exe or Invoke-RestMethod http://localhost:11434/api/tags.
  4. Configure Odoo. In Settings → AI Assistant Settings choose Local model and fill in:
    FieldValue
    Server TypeOllama (native API)
    Server URLhttp://localhost:11434 (or http://SERVER-IP:11434 if Ollama runs on another machine)
    Model NameExactly as shown by ollama list, for example qwen2.5:14b
    API KeyLeave empty (only needed behind a reverse proxy that requires one)
    Context Size16384 (use 8192 if memory is tight)
    Timeout180 seconds (use 300 or more on CPU-only machines)
  5. Click Test connection. You should see a green message with the response time. Then click Save.

Ollama on a separate server

  • On the Ollama machine set the environment variable OLLAMA_HOST=0.0.0.0:11434 and restart Ollama.
  • Open port 11434 in the firewall only for your Odoo server's IP address.
  • Never expose Ollama to the internet. Ollama has no login of its own, so for shared use put it behind a reverse proxy (nginx, Caddy) with an API key and HTTPS, and enter that key in the API Key field.

LM Studio, vLLM, llama.cpp and other servers

Choose Server Type OpenAI-compatible and enter the server's address including /v1, for example http://localhost:1234/v1 (LM Studio) or http://SERVER:8000/v1 (vLLM). In this mode the context size is set on the server itself.

Troubleshooting

You seeTry
"Could not reach the AI server"Is Ollama running? Check the URL and firewall. Test with the curl command above from the Odoo server itself.
"Model not found"The name must match ollama list exactly (including the tag after the colon). Run ollama pull for it.
Very slow answersUse a GPU, a smaller model, or a lower context size. The first request is slower because the model loads into memory.
"Took too long to answer"Increase the Timeout. If Odoo runs with workers, also raise limit_time_real in odoo.conf.
Wrong or empty answersSmall models struggle with structured output. Try a 14B+ model, and avoid "thinking" model variants for speed.
3  Groq Free tier
  1. Create an account at console.groq.com.
  2. Open API Keys, click Create API Key and copy the key (it starts with gsk_). You will only see it once.
  3. In Odoo Settings → AI Assistant Settings, choose Groq, paste the key and pick a model.
  4. Click Save.
Groq's free tier has rate limits, and the models available depend on your account. If the selected model is not available to your key, the assistant automatically switches to one that is.
4  OpenAI (ChatGPT) API key
  1. Sign in at platform.openai.com and add billing credits (the API is billed separately from ChatGPT subscriptions).
  2. Open API keys, create a secret key and copy it (starts with sk-).
  3. In Odoo choose OpenAI, paste the key, and type a Model id, for example gpt-5-mini. Any chat model id from OpenAI's models page works.
  4. Click Save.
5  Claude (Anthropic) API key
  1. Sign in at console.anthropic.com and add credits.
  2. Open API Keys, create a key and copy it (starts with sk-ant-).
  3. In Odoo choose Claude, paste the key, and enter a Model id, for example claude-sonnet-5-5.
  4. Click Save.
6  Google Gemini API key
  1. Open Google AI Studio and create an API key (starts with AIza).
  2. In Odoo choose Google Gemini, paste the key, and enter a Model id, for example gemini-flash-latest.
  3. Click Save.
Model names change often. Providers retire and add models regularly, so the model field for OpenAI, Claude and Gemini is free text. If you see a "model not available" message, copy a current model id from the provider's documentation.
7  Control who can ask what Security

Open AI Assistant → User Module Access and click New. Choose the user, pick the Allowed Modules, or switch on AI Super User. The assistant applies these rules in order:

UserWhat the assistant can query
Odoo administratorEverything
AI Super UserEverything
No rule definedEverything the user can already access (open by default)
Rule with modulesOnly those modules
Rule with no modulesNothing (fully blocked)
Because users without a rule are unrestricted, create a rule for every user whose access you want to limit.
Security & privacy

Designed to be safe with business data

Strictly read-only

Only search_count, search_read and read_group are allowed. The assistant cannot create, edit or delete records, and plans are parsed as data, never executed as code.

Runs as the logged-in user

Queries use the user's own access rights and record rules, so nobody sees data they could not already open in Odoo.

Clear data flow

With a cloud provider, the AI receives the question, the names and labels of the few relevant models and fields, and up to 50 result rows used to write the answer. With a local model, none of it leaves your network.

Keys and output handled carefully

API keys are stored in Odoo system parameters, visible to administrators only, and Gemini keys are sent in a header rather than in the URL. Answers are HTML-escaped before display.

FAQ

Common questions

Can the assistant change or delete my data?

No. It is limited to read-only queries, and every query runs with the asking user's own permissions.

Is my whole database sent to the AI?

No. Only the models relevant to the question are described to the AI, plus the few result rows needed to phrase the answer. With a local model nothing leaves your server.

Which languages can I ask in?

The assistant follows the language abilities of the model you choose. Large cloud models handle many languages well. Small local models are usually strongest in English, so test with your own language before rolling out.

How much do the AI providers cost?

This module is free under LGPL-3. Groq and Gemini offer free tiers with limits. OpenAI and Claude bill per use. A local model costs only your own hardware.

Does it need a powerful computer for local models?

A GPU makes local models fast. CPU-only machines work but answers can take a minute or more. See the Ollama guide above for memory estimates.
